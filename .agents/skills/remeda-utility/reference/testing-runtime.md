- Use Remeda's own utilities in tests when applicable (`prop`, `constant`, etc.).
- Runtime tests cover supported inputs. Remeda assumes well-typed input and leaves the outcome of anything the types reject unspecified, thrown errors included, so pinning it (in `known issues!` blocks too) would promise behavior we don't stand behind. `@ts-expect-error` on the input under test is for supported inputs the types can't express: a non-array iterable in `pipe`, a consumer with `exactOptionalPropertyTypes` off.
- Test inputs, property-test generators included, are dense arrays. Holes get whatever the implementation naturally does (skipped, read as `undefined`, or kept), which stays free to change with it.
- On an array, lazy-only behavior (the items processed so far as `data`, the sentinel, item-by-item call order) exists only in a fused sequence, which `pipe` builds only when one of its functions can end the iteration early. Put `forceFusion()` (`test/forceFusion.ts`) in the sequence, `pipe([1, 2, 3], forceFusion(), forEach(callback))`: a pass-through step marked as able to end the iteration, which throws when its sequence doesn't fuse.
- Lazy callbacks: verify the callback receives the items processed so far with a `vi.fn<LazyCallback<unknown[], unknown>>` mock returning `[...data]`, asserted per call with `toHaveNthReturnedWith`. The spread is load-bearing: `pipe` reuses one `data` buffer, so asserting on the reference after the pipe finishes compares the complete array and passes for the wrong reason. Template: `provides the items processed so far to the callback` in `forEach.test.ts`.
- A lazy-callback mock whose call arguments are asserted on declares every parameter up to `data` (`(value, index, data) => ...`, one more for `mapWithFeedback` and `zipWith`) or is a bare `vi.fn()` (`length` 0), so it receives the real items. Evaluated lazily (a fused sequence, or a non-array input), a shorter mock receives `UNEXPECTED_ACCESS_SENTINEL` as `data` (and, in `map`, the slot as a 4th argument); comparing the sentinel to an array, or printing it in a failed assertion's diff, throws its `Remeda: ...` error.
