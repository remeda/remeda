# A6 variant screening (branch 144fdc8b, 2026-10-07)

Agent sandbox, relative screen only: each process ran the branch next to up to 4 variants (`agent/a6-run.sh`), rotation 0 (branch first) and rotation 1 (branch last), tier 1 plus the batch's target flows, sizes XS/S/C/M/Mx64/x64/x1 (L left out), scale 0.25, `--source dist`, P2 pollution, no native. Raw runs: `results/a6/b<batch>-r<rotation>.json`; per-variant numbers: `results/a6/screen.txt` and `screen.json` (`agent/screen.mjs`).

Ratios are variant/branch (< 1 = the variant is faster), geomeans of the per-entry p75 ratio (mean when the branch's p75 is under 1 us). "Target" is the variant's `targets` flow from `variants/index.json` (without L); "T1" is every tier 1 entry measured in the same process (153).

Rules: drop only on clear evidence, i.e. no win on the target flow in either rotation (target geomean >= 1.00 in both), or a tier 1 slowdown clearly beyond noise (a tier 1 entry above 1.08 in both rotations that the variant's code path explains). Borderline variants are kept for confirmation. `identity-controls` and `sentinel-module` are design candidates and are kept whatever their timing; `sentinel-pure` is dropped without screening (tsdown strips its annotation, so the published dist is unchanged).

## identity-controls v1 vs v2 (follow-up)

`identity-controls-v2` is `identity-controls` plus one `typeof result === "symbol"` guard around the four control comparisons in `processItem` and `processSingleLazyStep` (the only dispatch sites), so an emitted item that is not a symbol pays one type check instead of four identity comparisons. Screen: one process per rotation with branch, v1 and v2, rotations 0, 1 and 2 (every copy in every position once), the guard subset `T1G` plus both targets (no L), scale 0.25 (`results/a6/icv2-r*.json`, `agent/tiers-compare.mjs`, `results/a6/icv2-screen.json`).
